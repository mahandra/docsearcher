# DocQA

A Django web app where users upload documents (PDF, DOCX) and ask questions about them.
Answers are generated by an LLM using retrieval-augmented generation (RAG) and cite their sources.

This is a learning/portfolio project, built phase by phase. **Current state: phase 2** —
a streaming LLM chat (phase 1) plus document ingestion: PDF/DOCX files are parsed, chunked,
embedded with Voyage AI in a Celery worker and stored in PostgreSQL/pgvector. Answering
questions about documents (retrieval) arrives in phase 3.

## Quick start

Requirements: Docker with Compose v2, GNU make. Optionally [uv](https://docs.astral.sh/uv/)
for running tools on the host.

```bash
cp .env.example .env          # set DJANGO_SECRET_KEY, ANTHROPIC_API_KEY, VOYAGE_API_KEY
make up                       # start db, redis, web and worker
make migrate                  # create tables
# then open http://localhost:8000, sign up and start a chat
```

| Command | What it does |
|---|---|
| `make up` / `make down` | Start / stop all services |
| `make migrate`, `make makemigrations` | Database migrations |
| `make test` | Run the test suite in Docker (never calls the real API) |
| `make lint`, `make fmt` | Ruff checks / formatting |
| `make shell`, `make superuser`, `make logs` | Django shell, admin user, web + worker logs |

Running on the host instead: `uv sync`, then `uv run pytest` or `uv run python manage.py ...`
(the database from Docker is exposed on `localhost:5434`).

Changes to `.env` are picked up only when containers are recreated:
`docker compose up -d --force-recreate web worker`. After adding dependencies run `make build`.

### Configuration

| Variable | Default | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | Anthropic API key |
| `LLM_MODEL` | `claude-opus-5-5` | Model ID; prices for known models are in `chat/pricing.py` |
| `LLM_EFFORT` | `low` | Reasoning effort (`low`…`max`); empty = API default |
| `LLM_MAX_TOKENS` | `16000` | Upper bound for one reply |
| `LLM_MAX_HISTORY_MESSAGES` | `20` | How many recent messages are sent as context |
| `LLM_MAX_RETRIES` | `3` | Retries for transient API errors |
| `LLM_TIMEOUT_SECONDS` | `120` | Request timeout |
| `VOYAGE_API_KEY` | — | Voyage AI key (embeddings) |
| `EMBEDDING_MODEL` | `voyage-4` | Embedding model (1024-dim output) |
| `CHUNK_SIZE_TOKENS` / `CHUNK_OVERLAP_TOKENS` | `500` / `75` | Chunk size and overlap (estimated tokens) |
| `DOCUMENT_MAX_UPLOAD_MB` | `20` | Upload size limit |

## Architecture

```
Browser ──HTMX POST──▶ message_create ──▶ saves user Message, returns placeholder
   │
   └─EventSource GET─▶ message_stream (async) ──▶ ChatService.stream_reply()
                         │ SSE: thinking/token/done/failed     │
                         ◀─────────────────────────────────────┤ AsyncAnthropic
                                                               │ messages.stream()
                                                               ▼
                                              saves assistant Message
                                              (content, status, tokens, cost)
```

- **Served via ASGI (uvicorn).** A streamed answer keeps the HTTP connection open for tens of
  seconds; async views wait on the network without occupying a worker.
- **Service layer (`chat/llm.py`).** The only module that imports the Anthropic SDK. It builds the
  message history from the database, loads the system prompt from `chat/prompts/system.md`,
  streams the reply and persists it. Views receive domain events (`ThinkingStarted`, `TextDelta`,
  `Completed`, `Failed`), so the SDK can be mocked or replaced without touching the web layer.
- **History.** The API is stateless: the conversation is resent on every request (and billed as
  input tokens), limited to the last `LLM_MAX_HISTORY_MESSAGES` messages. The history always
  alternates user/assistant and starts with a user turn.
- **Retries.** The SDK retries failures to open a request (429, 5xx, 529 overloaded, network) with
  exponential backoff. Errors inside an open stream are retried by the service — but only before
  the first token reached the browser. After that, the partial answer is saved with status
  `interrupted` instead of being regenerated.
- **Cost tracking.** Every assistant message stores model, input/output tokens, `stop_reason` and
  estimated cost (`chat/pricing.py`). Interrupted streams record best-effort usage.
- **Streaming transport.** Server-Sent Events with a native `EventSource` (`chat/static/chat/stream.js`)
  rather than the HTMX SSE extension: we stream one reply and must close the connection
  explicitly — `EventSource` otherwise reconnects and would trigger another, billed generation.
  The server additionally claims each generation with an atomic conditional `UPDATE`, so
  reconnects or a second tab cannot start a duplicate.
- **Cancellation.** If the browser disconnects, the API stream is closed immediately (stopping
  token generation) and the partial answer is kept.
- **Security basics.** All data is scoped to the logged-in user (Django auth); LLM output is
  treated as untrusted and always rendered as escaped text.

### Document ingestion (phase 2)

```
Browser ──HTMX upload──▶ document_upload ──▶ validate (size, extension, magic bytes, duplicate)
   │                          │                  save Document(status=uploaded)
   │                          └─ transaction.on_commit ─▶ Redis ─▶ Celery worker
   │                                                                 │ process_document
   └─HTMX poll every 2s─▶ document_row                               ▼
       (stops when ready/failed)              detect type → parse (pypdf / python-docx)
                                              → chunk (recursive, with overlap)
                                              → embed (Voyage AI, input_type="document")
                                              → atomically replace Chunks (pgvector, HNSW)
```

- **Parsing** keeps where text came from — PDF page numbers, DOCX headings — so phase 3 can cite
  sources. Scanned PDFs (no text layer) and password-protected files fail with a clear message.
- **Chunking** (`documents/chunking.py`) splits at paragraphs → lines → sentences → words and packs
  pieces into ~500-token chunks with ~75 tokens of overlap (taken from trailing sentences when a
  paragraph is longer than the overlap). Chunks may span PDF pages; a DOCX heading always starts a
  new chunk. Token counts are character-based estimates.
- **Embeddings** (`documents/embeddings.py`) — the only module using the Voyage SDK. Anthropic
  offers no embeddings API; Voyage `voyage-4` is multilingual (mixed English/Russian documents).
  Texts are batched under count and token limits; truncation is disabled so nothing is silently cut.
  Exact token usage and cost are stored per document.
- **Celery task** is idempotent (late acks, chunks replaced in one transaction), runs network calls
  outside transactions, retries transient provider errors with exponential backoff and jitter, and
  fails fast on permanent ones (e.g. invalid API key).
- **Storage**: each `Chunk` has a `vector(1024)` column with an HNSW index for cosine distance.
  Changing the embedding model or dimension requires re-embedding all documents.

### Project layout

```
config/            Django settings (env-driven), URLs, ASGI app
chat/
  llm.py           LLM service layer (Anthropic SDK wrapper)
  pricing.py       Model prices and cost estimation
  prompts/         System prompt(s)
  models.py        Conversation, Message
  views.py         Pages, HTMX endpoints, SSE stream
  templates/ static/
documents/
  parsing.py       PDF/DOCX text extraction with page/heading metadata
  chunking.py      Recursive chunker with overlap
  embeddings.py    Embedding service layer (Voyage AI SDK wrapper)
  tasks.py         Celery ingestion task
  models.py        Document, Chunk (pgvector)
  views.py forms.py signals.py templates/
templates/         Base layout, login/signup
tests/             pytest suite with fake Anthropic and Voyage clients (no real API calls)
```

## Roadmap

1. **Basic LLM chat** with streaming, conversation history and cost tracking — ✅ done
2. **Document ingestion:** parsing, chunking, embeddings via Celery, storage in pgvector — ✅ done
3. **Retrieval + answering:** hybrid search (pgvector + Postgres full-text), citations
4. **Evaluation:** test set of questions, eval script, Langfuse tracing
5. **Production polish:** structured outputs, caching, model fallback, prompt-injection defenses
